# Wintrail Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A VS Code extension holding a private, encrypted work-achievements log (write without unlocking), a dashboard with a heatmap and Year in Review, a Teams standup drafter, and Break Buddy reminders.

**Architecture:**
- Pure logic lives in `src/core/` (no `vscode` import; unit-tested with vitest).
- VS Code wiring lives in `src/host/`.
- The sidebar UI is a Svelte app in `webview/` that only renders state messages and sends intents. The webview never sees keys or ciphertext.
- Crypto and file-safety patterns are copied from Authora (`~/workspace/extentions/authora/src/core/envelope.ts` and `vault.ts`).

**Tech Stack:**
- TypeScript 5.6, esbuild 0.28 with esbuild-svelte, Svelte 5, vitest 4.
- hash-wasm (Argon2id), `node:crypto` (X25519, HKDF, AES-256-GCM, HMAC-SHA256).
- VS Code engine `^1.85.0`.

**Spec:** `docs/superpowers/specs/2026-11-25-wintrail-design.md`, with mockups in `docs/superpowers/specs/mockups/`. Read both.

## Global Constraints
- Extension id `NiravPatel15.wintrail`; display name "Wintrail"; command and setting prefix `wintrail.`; MIT licence.
- No network calls of any kind. No telemetry.
- Nothing about an entry (text, timestamp, project, branch, tags, star, impact) is readable on disk without the password. Edit/delete target ids sit inside the ciphertext. Plaintext is padded to 256-byte buckets.
- Argon2id defaults: m=65536, t=3, p=1. KDF bounds when reading files are as in Authora's `KDF_LIMITS`.
- Settings use `"scope": "application"`.
- Webview messages are validated as in Authora's `src/shared/validate.ts`. Strict CSP with a nonce script.
- Git runs only through `execFile`, never a shell.
- Commits use repo-local identity "NIRAV PATEL" <90965107+NIRAV-PATEL-15@users.noreply.github.com>, with **no Co-Authored-By or AI attribution lines**. No pushing or publishing without the owner's OK.
- Exact-pinned devDependencies. CI and release workflows copied from Authora (pinned action SHAs, two-job release).

## Review Focus
1. **Local time and dates:** "today", day grouping, the heatmap, the streak and the standup's previous working day use the user's local timezone, including across a DST change. Test: an entry at 23:30 local belongs to that day, not the UTC day (Task 3).
2. **Large logs:** a year of heavy use (5,000 entries plus edits) must replay in under 1 s, and quick-add must stay O(1). Test: replay benchmark (Task 2).
3. **Git edge cases:** git not installed, a workspace folder that isn't a repo, several repos, detached HEAD, or no `user.email`. The standup still renders from the log and never throws. Test (Task 4).
4. **Concurrency:** a quick-add in window B while window A compacts or re-keys must not be lost. Test: a two-store race (Task 2).
5. **Clock jumps (sleep or resume):** Break Buddy must not fire a burst of reminders after the laptop wakes. A gap larger than the idle threshold counts as a break. Test (Task 6).

**Interfaces (produces):**
- `generateKeys(): { publicKey: Buffer /*X25519 raw 32B*/, privateKey: Buffer /*pkcs8 der*/, macKey: Buffer /*32B*/ }`
- `wrapKeys(k, password, cost?): Promise<WrappedKeys>` where `WrappedKeys = { v: 1, kdf: KdfParams, pub: string /*b64*/, iv: string, ct: string /*AES-GCM of {priv, mac}*/ }`
- `unwrapKeys(w: WrappedKeys, password): Promise<{ privateKey, macKey, wrapKey: Buffer }>`, which throws `WrongPasswordError`.
- `sealTo(publicKey: Buffer, plaintext: Buffer): SealedBlob` where `SealedBlob = { epk: string, iv: string, ct: string }` (ephemeral X25519 → ECDH → HKDF-SHA256 with info `"wintrail-seal-v1"` → AES-256-GCM).
- `openSealed(privateKey: Buffer, b: SealedBlob): Buffer`, which throws on tampering.
- `mac(macKey: Buffer, data: string): string` (HMAC-SHA256, base64) and `verifyMac(macKey, data, tag): boolean` (constant-time).
- `pad(buf: Buffer): Buffer` and `unpad(buf): Buffer`: a 4-byte length prefix, padded to a multiple of 256.

- [ ] Tests:

  - `openSealed` with the wrong private key throws;
  - a flipped ct byte throws;
  - `unwrapKeys` with the wrong password throws `WrongPasswordError`;
  - `pad` gives the same output length for 1-byte and 250-byte inputs (256), and 300 bytes gives 512;
  - `verifyMac` rejects a modified data string.
- [ ] Run them and watch them fail. Implement. Run `npm test`, which should pass. Commit `feat: key material, sealed boxes, MAC`.

### Task 2: Log store (`src/core/records.ts`, `src/core/logstore.ts`)
**Interfaces (consumes):** everything from Task 1. **(produces):**
- `type EntryData = { text: string; at: number; project: string; branch: string; tags: string[]; star: boolean; impact: "normal"|"high" }`
- `type Entry = EntryData & { id: string; lockedAdd: boolean /*needs confirm*/ }`
- `type Plan = { day: string /*YYYY-MM-DD local*/; text: string }`
- Record kinds inside the ciphertext: `add {id, data}`, `edit {target, data}`, `delete {target}`, `confirm {target}`, `plan {plan}`. On disk, one JSONL line is `{ r: string /*random id*/, s: SealedBlob, m?: string /*MAC over r+JSON(s), only when written unlocked*/ }`.
- `class LogStore(dir: string, cost?: KdfCost, now?: () => number)` with:
  - `exists()`, `create(pw)`, `unlock(pw)`, `unlockWithKey(wrapKey)`, `lock()`, `isUnlocked`, `exportWrapKey()`
  - `add(data: EntryData): Promise<string /*id*/>`, which works while locked; when unlocked it also attaches a MAC
  - `entries(): Entry[]` (unlocked only, sorted by `at` descending); `plans(): Plan[]`
  - `edit(id, data)`, `remove(id)`, `confirm(id)`, `savePlan(plan)` (all unlocked only, MAC'd)
  - `forgedCount: number`, the number of ignored records with a missing or invalid MAC (edit/delete/confirm/plan only)
  - `changePassword(old, new)`: new keys, then re-seal everything with MACs, written as an atomic rewrite
  - `compactIfNeeded(threshold = 200 superseded records)`
  - `refresh(): boolean`
  - `exportBackup(): string` and `importMerge(text, pw): Promise<{ added: number; skipped: number }>`
- Files: `vault.json` (WrappedKeys) and `entries.jsonl`. Writes use Authora's lock file plus durable atomic write plus `.bak`. Appends use `O_APPEND` and fsync under the lock file.
- **Replay rules:**
  - `add` records are always accepted. `lockedAdd` is true when there's no valid MAC.
  - `edit`, `delete`, `confirm` and `plan` records apply only with a valid MAC.
  - The last valid edit wins, and a delete is final.
- **Re-key detection:** `vault.json` `pub` differs from the in-memory value, so lock and throw `VaultChangedError`.

- [ ] Tests:
  - an add while locked is readable after unlock, with `lockedAdd` true;
  - an add while unlocked has `lockedAdd` false;
  - after `confirm`, the entry's `lockedAdd` is false;
  - edit then delete replay correctly;
  - a forged `delete` (appended by a writer without the macKey) is ignored and `forgedCount` is 1;
  - disk bytes never contain the entry text, project, tag or the target id;
  - `changePassword` means old password plus an old copied `vault.json` can't open new records, and all entries survive;
  - two stores on one dir: B appends while A compacts, and no entry is lost (Review Focus 4);
  - corrupted `entries.jsonl` last line (torn write) is skipped and the rest loads;
  - 5,000 entries plus 2,000 edits replay in < 1000 ms (Review Focus 2);
  - `importMerge` re-seals under the current keys, skips duplicates by (text, at), and writes `.pre-import.bak` first.
- [ ] Fail, then implement, then pass. Commit `feat: encrypted append-only log store`.

### Task 6: Break scheduler (`src/core/breaks.ts`)
**Interfaces (produces):**
- `type BreakKind = "eyes"|"stretch"|"water"`.
- `type BreakConfig = { intervals: Record<BreakKind, number /*min*/>; enabled: Record<BreakKind, boolean>; style: Record<BreakKind, "notification"|"screen">; eyeSeconds: number; stretchSeconds: number; snoozeMin: number; idleMin: number; resetMin: number; workHours?: { start: string; end: string } }`
- Defaults and ranges come exactly from the spec table, via `DEFAULT_BREAKS` and `clampBreakConfig(partial): BreakConfig`.
- `class BreakScheduler(cfg, now: () => number)` with:
  - `activity()`: called on edits, selection changes and focus;
  - `tick(): BreakKind | null`: called every 15 s; returns a due reminder, at most one at a time;
  - `done(kind)`, `snooze(kind)`, `skip(kind)`;
  - `focus(untilTs: number | null)`;
  - `setConfig(cfg)`;
  - `weekStats(): Record<BreakKind, { taken: number; due: number }>`.
- Active time accrues only between activity events less than `idleMin` apart. A gap of at least `resetMin` resets all counters (a real break). A wall-clock jump larger than `idleMin` counts as a gap (Review Focus 5). No reminders while focused or outside work hours.
- [ ] Tests:

  - idle 6 min pauses accrual;
  - a 5+ min gap resets;
  - snooze defers by `snoozeMin`;
  - only one pending at a time;
  - focus mutes;
  - work hours mute;
  - a sleep jump of 3 h gives no burst (`tick()` returns null and the counters reset);
  - `clampBreakConfig({ intervals: { eyes: 1 } })` clamps to 5.
